# ona_github_app_integration (List Resource)

Lists organization-owned GitHub App integrations, including pending installations. Uses saved metadata only; credentials and the local credentials_version marker are omitted.

Terraform Query requires Terraform CLI `>= 1.14`. This list resource discovers organization-managed GitHub App integrations, including those awaiting browser installation. It excludes the shared GitHub App and other integration types.

Discovery uses the same [App classification](../resources/github_app_integration.md#app-classification) as resource refresh and import: at least one saved App ID, slug, or client ID must differ from the associated canonical GitHub App definition. Matching values are classified as shared, even with locally configured credentials.

With `include_resource = true`, Query includes saved App and installation metadata and can generate resource and import blocks. It supplies no credential values or rotation version. Empty or null credential placeholders in generated configuration are safe to keep for import. Query does not require App secrets, authenticate to GitHub, or validate installation access.

## Example Usage

Save the query in a `.tfquery.hcl` file alongside your configured Ona provider:

```terraform
list "ona_github_app_integration" "all" {
  provider         = ona
  include_resource = true
}
```

Generate configuration into a new file:

```shell
terraform query -generate-config-out=github-app-integrations.tf
```

Review the generated addresses, then plan and apply the imports without supplying credential values or a `credentials_version`. Import reads the existing integration without rotation. If a generic `ona_integration` resource already owns an object, complete the state-only handoff described in the [GitHub App integration resource](../resources/github_app_integration.md#adopt-from-ona_integration) before importing it here. Each remote integration must have one owning Terraform address.
